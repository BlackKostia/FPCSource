# ADR-0009: Зрізи пам'яті `TSpan<T>` / `TReadOnlySpan<T>`

- Статус: прийнято
- Дата: 2026-10-20

## Контекст
Розділ 3.2 дорожньої карти: легковагова структура `(Ptr: ^T; Length:
SizeInt)` з перевіркою меж «при `-Cr`», що представляє неперервний
піддіапазон статичного чи динамічного масиву, рядка або `TBytes` без
копіювання й алокацій, і дозволяє безпечно передавати неперетинні сегменти
масиву в паралельні задачі `System.Threading`.

Експеримент (до написання коду): у тілі методу узагальненого типу діють
налаштування модуля, де дженерик **оголошено**. `-Cr` модуля, що
спеціалізує дженерик, і `{$IFOPT R+}` у тілі методу на код спеціалізації
не впливають; RTL і пакети збираються без `-Cr`.

## Рішення
1. Модуль `spans` (+ `System.Spans`) у `packages/rtl-objpas`, поруч зі
   `smartptrs`; залежить лише від `sysutils`.
2. Два типи: `TReadOnlySpan<T>` і `TSpan<T>` (запис + неявне
   перетворення на `TReadOnlySpan<T>`); поля — лише `Data` і `Length`.
3. **Межі перевіряються завжди** (`Items`, `Slice`, `Chunk`, `Create` з
   діапазоном, `CopyFrom`), `ERangeError`. Перевірки без переповнення
   (`ACount <= ALength - AStart`). Без перевірок — `for..in` і `Data`.
4. `Chunk(I, N)` — детерміноване розбиття без переповнення:
   перші `Length mod N` частин мають на елемент більше.
5. `CopyFrom`/`Fill`/`ToArray` присвоюють елементи (не `Move`), тож керовані
   типи коректні; перекриття в `CopyFrom` — копіювання у зворотному
   напрямку.
6. Рядки: `SpanOf` (лише читання) і `MutableSpanOf` (`UniqueString` перед
   записом, щоб не змінити спільний рядок).
7. Помічники перевірок (`SpanIndexError` тощо) — неузагальнені процедури в
   інтерфейсі: виклик винятку не роздуває inline-методи.

## Розглянуті альтернативи
- **Перевірка лише при `-Cr`** (як вимагала дорожня карта): технічно
  неможлива для дженериків з RTL (див. «Контекст»). Варіант «два набори
  методів, `Items` і `UncheckedItems`» відхилено: безпечний доступ має бути
  типовим; для швидкості є `for..in`.
- **Один тип з прапорцем «лише читання»**: перевірка під час виконання
  замість типу; `const`-коректність втрачається.
- **Відстеження часу життя** (як `ref struct` у C# чи позичання в Rust):
  потребує змін мови; час життя задокументовано як правило використання.
- **Зберігання посилання на динамічний масив, щоб утримати його живим**:
  робить зріз керованим типом (лічильник посилань на кожну копію) і не
  працює для статичних масивів і рядків.

## Наслідки
- Зріз не продовжує життя джерела; використання після `SetLength`,
  звільнення масиву чи зміни рядка — помилка програми, яку перевірка меж не
  ловить.
- Неперетинні зрізи з різних потоків — без синхронізації (Helgrind на
  паралельних тестах: 0 повідомлень).
