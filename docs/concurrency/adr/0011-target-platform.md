# ADR-0011: Цільова платформа — x86_64-linux

- Статус: прийнято
- Дата: 2026-10-20

## Контекст
Основна аудиторія гілки `feature/concurrency` — серверні та настільні
програми на x86_64-Linux. Частина коду гілки вже фактично прив'язана до цієї
платформи: перемикання контексту `TFiber` (asm System V AMD64), стеки
файберів через `mmap`, `fpvalgrind`, ThreadSanitizer (`fpctsan`,
`-fsanitize=thread`). Водночас документи обіцяли роботу на macOS, Windows та
ARM64, а для `fcl-eventloop` лежать бекенди kqueue та IOCP, яких ніхто не
перевіряв. Перенесення на інші платформи потребує окремого коду (ABI,
модель пам'яті ARM, SEH, IOCP) та залізa для перевірки, якого немає.

## Рішення
1. **x86_64-linux — єдина підтримувана й тестована ціль гілки.** Кожна
   зміна перевіряється на ній: повний набір `tests/` проти базової лінії,
   тести пакетів, `tests/concurrency/run-tsan.sh`, бенчмарки
   `tests/concurrency/`. Оптимізації можуть спиратися на Linux
   (epoll/io_uring, futex, `mmap`) і x86_64 (модель пам'яті TSO, asm).
2. **Мінімальна реструктуризація**: модулі лишаються у своїх пакетах; нових
   шарів абстракції платформи чи фасадних пакетів не вводимо.
3. **Пакети, код яких лише для x86_64-linux, обмежені в `fpmake.pp`**:
   `fcl-coroutines` — `OSes := [linux]`, `CPUs := [x86_64]`.
4. **Наявний код для інших ОС не видаляється, але не підтримується**:
   бекенди kqueue (`src/bsd`) та IOCP (`src/win`) у `fcl-eventloop`
   збираються як і раніше, проте не тестуються; переносні модулі
   (`System.Threading`, `SyncObjs`, `smartptrs`, `spans`) не обмежуються.

## Розглянуті альтернативи
- **Єдина кодова база з шаром платформи (`system.concurrency.pp`) і
  поетапним перенесенням на Windows x64, Linux ARM64, macOS ARM64**:
  потребує реструктуризації пакетів, нового asm (Win64 ABI, AArch64),
  перевірки слабкої моделі пам'яті ARM на реальному залізі та
  Windows-машини для IOCP/SEH. Відкладено до появи потреби.
- **Обмежити всі нові пакети до x86_64-linux у `fpmake.pp`**: переносний
  код без потреби став би недоступним на інших цілях, де він працює.

## Наслідки
- Документи (`roadmap.md`, README) обіцяють лише x86_64-linux.
- `fcl-coroutines` на інших Unix більше не збирається (раніше збирався
  лише на x86_64, а на інших ОС не перевірявся).
- Перенесення на іншу платформу — окреме рішення з власним ADR.
