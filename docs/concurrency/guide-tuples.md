# Посібник користувача: Кортежі (Tuples) та деконструкція у Free Pascal

## 1. Вступ та мотивація

У класичному Pascal та Delphi повернення двох чи більше значень із функції завжди вимагало компромісів:
1. **Використання `out` або `var` параметрів**:
   ```pascal
   // Традиційний підхід через out-параметри:
   procedure DivRem(A, B: Integer; out Quot, Rem: Integer);
   // Неможливо зручно використати у функціональних виразах або неблокувальних ланцюжках
   ```
2. **Створення штучних типів `record`**:
   ```pascal
   type
     TDivRemResult = record
       Quot, Rem: Integer;
     end;
   function DivRem(A, B: Integer): TDivRemResult;
   // Вимагає засмічення секції type десятками дрібних одноразових структур
   ```

У сучасних мовах (**Rust, C#, Python, Go**) базовим інструментом для розв'язання цієї задачі є **кортежі (Tuples)** та **деконструкція значень**:
```pascal
// Цільовий синтаксис у Free Pascal:
function DivRem(A, B: Integer): (Integer, Integer);
begin
  Result := (Integer(A div B), Integer(A mod B));
end;

// Виклик та розпакування:
var (Q, R) := DivRem(10, 3);
```

У Free Pascal (`feature/concurrency`) реалізовано повноцінну нативну підтримку кортежів, деконструкції та одночасного обміну змінними за перемикачем:
```pascal
{$modeswitch tuples}
```

---

## 2. Активація перемикача режимів

Підтримка кортежів вмикається директивою:
```pascal
{$mode objfpc}{$H+}
{$modeswitch tuples}
```

> [!NOTE]
> Кортежі безшовно поєднуються з іншими розширеннями мови:
> - `{$modeswitch arrowfunctions}` — передача та повернення кортежів у стрілкових лямбдах `(A, B) => (A + B, A - B)`;
> - `{$modeswitch implicitgenerics}` — автоматичне виведення типів дженериків із кортежними типами `IFuture<(Integer, string)>`.

## 3. Оголошення типів кортежів

Кортеж у компіляторі є анонімним строго типізованим записом (`trecorddef`), що розміщується безпосередньо на стеку або в регістрах без жодних динамічних алокацій у heap (zero-overhead).

### 3.1. Позиційні кортежі
У позиційному кортежі елементи визначаються списком типів через кому:
```pascal
var
  Pair: (Integer, string);
  Triple: (Double, Double, Boolean);

function GetCoordinates: (Double, Double);
```

### 3.2. Іменовані кортежі
Поля кортежу можуть мати власні ідентифікатори:
```pascal
var
  Person: (Name: string, Age: Integer);
  Stats: (Count: Integer, Sum: Int64);

function CountAndSum(const Arr: array of Integer): (Count: Integer, Sum: Int64);
```

## 4. Літерали кортежів

Літерал кортежу утворюється переліком виразів у круглих дужках через кому `(Expr1, Expr2, ...)`:
```pascal
var
  Tup: (Integer, string);
begin
  Tup := (42, 'Free Pascal');
  Result := (A div B, A mod B);
end;
```

Компілятор автоматично виводить типи полів кортежного літералу:
- Цілочисельні літерали (`42`, `100`) за замовчуванням типізуються як `Integer` (або `Int64`, якщо значення виходить за межі 32 біт);
- Рядкові літерали (`'Hello'`) типізуються як `string` (`AnsiString` / `UnicodeString`);
- Складні вирази, виклики функцій та змінні зберігають свій результуючий тип.

## 5. Деконструкція кортежів (Tuple Deconstruction)

Деконструкція дозволяє розпакувати елементи кортежу в окремі змінні за один вираз.

### 5.1. Розпакування в уже оголошені змінні
```pascal
var
  Q, R: Integer;
begin
  (Q, R) := DivRem(10, 3);
  WriteLn('Частка: ', Q, ', Остача: ', R);
end;
```

### 5.2. Розпакування з оголошенням локальних змінних (`var (A, B) := ...`)
Змінні створюються за місцем використання без потреби попередньо оголошувати їх у блоці `var`:
```pascal
procedure ProcessData;
begin
  var (Count, Sum) := CountAndSumPrimes(100);
  WriteLn('Знайдено: ', Count, ', Сума: ', Sum);

  var (Greeting, Answer) := ('Hello', 42);
  // Greeting має тип string, Answer має тип Integer
end;
```

Також підтримується альтернативна форма `(var A, var B) := ...` або `(var A, B) := ...`:
```pascal
(var MinVal, MaxVal) := FindExtremes(MyArray);
```

## 6. Одночасний обмін значеннями без тимчасових змінних (Swap)

Деконструкція вирішує класичну задачу перестановки змінних без потреби введення зайвої тимчасової змінної `Temp`:

### 6.1. Подвійний обмін
```pascal
// Раніше:
// Temp := X; X := Y; Y := Temp;

// Тепер:
(X, Y) := (Y, X);
```

### 6.2. Циклічний зсув кількох змінних
```pascal
(A, B, C) := (C, A, B);
```

### 6.3. Безпека для керованих типів (Managed Types)
Компілятор генерує оцінку правої частини в захищений тимчасовий стек перед присвоєнням лівої частини. Це гарантує нульові гонки та відсутність витоків пам'яті для керованих типів (`string`, `interface`, динамічні масиви):
```pascal
var
  S1, S2: string;
begin
  S1 := 'Free';
  S2 := 'Pascal';

  (S1, S2) := (S2, S1);
  // S1 = 'Pascal', S2 = 'Free'
end;
```

## 7. Доступ до елементів кортежу

Доступ до компонентів значення типу кортеж підтримується як за іменем, так і за номером позиції:

### 7.1. Позиційний доступ (`.Item1`, `.Item2`, ...)
Для будь-якого кортежу доступні поля `.Item1`, `.Item2`, `.Item3`, ...:
```pascal
var
  PosTup: (Integer, string);
begin
  PosTup := (100, 'items');
  WriteLn(PosTup.Item1); // 100
  WriteLn(PosTup.Item2); // 'items'
end;
```

### 7.2. Іменований доступ та універсальний фолбек
Для іменованих кортежів доступ можливий як за власним іменем, так і за позиційним псевдонімом `.ItemN`:
```pascal
var
  NamedTup: (Count: Integer, Sum: Int64);
begin
  NamedTup := (42, 9999999999);

  // Доступ за іменем:
  WriteLn(NamedTup.Count); // 42
  WriteLn(NamedTup.Sum);   // 9999999999

  // Позиційний фолбек (працює завжди):
  WriteLn(NamedTup.Item1); // 42
  WriteLn(NamedTup.Item2); // 9999999999
end;
```

## 8. Структурна еквівалентність типів (Structural Equivalence)

У стандартному Pascal записи (`record`) мають іменну типізацію (навіть записи з однаковими полями вважаються різними типами). Для кортежів діє **структурна типізація**:

> [!IMPORTANT]
> Два кортежі є повністю взаємозамінними та сумісними для присвоєння, якщо вони мають однакову кількість полів і відповідні типи полів сумісні між собою. Імена полів при цьому не перешкоджають сумісності!

```pascal
var
  Named: (X: Integer, Y: Integer);
  Pos: (Integer, Integer);
begin
  Named := (10, 20);
  Pos := Named; // Повна структурна сумісність: Pos.Item1 = 10, Pos.Item2 = 20
  Named := Pos; // Працює в обох напрямках
end;
```

## 9. Кортежі як параметри процедур та функцій

Кортеж можна передавати безпосередньо у виклики підпрограм як константний або значенням параметр:
```pascal
function FormatPerson(const Person: (Name: string, Age: Integer)): string;
begin
  Result := Person.Name + ' is ' + IntToStr(Person.Age) + ' years old';
end;

// Передача кортежного літералу:
Res := FormatPerson(('Bob', 25));
```

## 10. Інтеграція з багатопотоковістю (`System.Threading`)

Кортежі суттєво спрощують агрегацію результатів у паралельних задачах:
```pascal
var
  Task: specialize IFuture<(Integer, Integer)>;
begin
  Task := TTask.Future(() => DivRem(100, 7));
  var (Quot, Rem) := Task.Value;
end;
```

## 11. Продуктивність та оптимізації

1. **Zero-overhead (без виділення пам'яті в купі)**:
   Кортежі формуються компілятором як звичайні легкі структури пам'яті на стеку. Вони не створюють жодного навантаження на диспетчер пам'яті (Heap Manager).
2. **Оптимізація регістрів**:
   Кортежі невеликого розміру (до 16 байт на x86_64, наприклад два 32-бітні чи два 64-бітні цілі) передаються та повертаються безпосередньо через регістри CPU (`RAX`, `RDX`), усуваючи накладні витрати на копіювання пам'яті.
3. **Атомарний swap без гонок**:
   Конструкція `(A, B) := (B, A)` генерує збереження вихідних значень у тимчасових регістрах/стеку перед перезаписом, унеможливлюючи ефект випадкового затирання значень.
