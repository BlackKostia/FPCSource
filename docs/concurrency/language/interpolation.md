# Посібник користувача: інтерполяція рядків `$'...'` (`{$modeswitch interpolation}`)

Розділ 2.6 дорожньої карти ([roadmap.md](../roadmap.md)). Перемикач форку,
пропозиція 4.3 з `proposals/modern_pascal_productivity_and_web_vision.md`.

## 1. Навіщо

```pascal
WriteLn(Format('Замовлення #%d від %s: %.2f грн', [Order.Id, Order.Customer, Order.Total]));
```

`Format` перевіряє шаблон лише під час виконання. Якщо переплутати `%d` і
`%s` або пропустити аргумент, код компілюється, а падає з `EConvertError`,
та ще й на тій гілці, яка виконується рідко. Конкатенація з `IntToStr`
довга й погано читається. З `{$modeswitch interpolation}`:

```pascal
WriteLn($'Замовлення #{Order.Id} від {Order.Customer}: {Order.Total:0:2} грн');
```

Кожен вираз у `{...}` має тип, і компілятор перевіряє його, як будь-який
інший вираз. Форматування — те саме, що в `Write`/`WriteStr`, з тими самими
специфікаторами `:ширина:точність`. Нової мови форматів учити не треба.

## 2. Увімкнення

```pascal
{$mode objfpc}{$H+}
{$modeswitch interpolation}
```

Діє в усіх режимах. Без перемикача `$'...'` — синтаксична помилка, як і в
FPC. Шістнадцяткові константи (`$FF`) перемикач не змінює: інтерполяцію
розпізнає лише `$`, після якого одразу йде апостроф.

## 3. Синтаксис

```text
$'текст {вираз} текст {вираз:ширина} текст {вираз:ширина:точність} ...'
```

| Запис | Значення |
|---|---|
| `{X}` | значення виразу `X` |
| `{X:8}` | вирівняне праворуч у полі ширини 8 |
| `{X:0:2}` | дійсне число з двома знаками після коми |
| `{X:W}`, `{X:W + 2:P}` | ширина й точність можуть бути виразами |
| `{{`, `}}` | символи `{` і `}` |
| `''` | апостроф, як у звичайному рядку |

У виразі можна писати що завгодно, зокрема виклики функцій і рядкові
константи у звичайних апострофах:

```pascal
$'{UpperCase(Name)} має {Length(Items)} позицій, перша: {Items[0]}'
$'Код: {IntToHex(Id, 4)}, статус: {IfThen(Paid, 'оплачено', 'ні')}'
$'Вкладено: {$'[{Id}]'}'
```

Вираз закінчується першою `}` поза рядковими константами. Інтерпольований
рядок займає один рядок вихідного тексту. Вкладений `$'...'` дозволений,
якщо в його виразах немає апострофів.

## 4. Як виводяться значення

Так само, як у `WriteLn`:

| Тип | `{X}` | Приклад |
|---|---|---|
| цілі (`Integer`, `Int64`, `QWord` …) | десятковий запис | `-7`, `18446744073709551615` |
| дійсні (`Double`, `Extended` …) | **науковий формат**, як у `WriteLn` | ` 1.2345000000000000E+003` (`Double`) |
| дійсні з точністю | `{X:0:2}` | `1234.50` |
| `Boolean` | `TRUE` / `FALSE` | |
| переліки | ім'я значення | `Green`, `stPaid` |
| `Char`, рядки всіх видів | як є | |
| `PChar` | рядок, на який вказує | |
| класи, записи, вказівники, множини | **помилка компіляції** | `{Obj.ToString}`, `{IntToHex(PtrUInt(P), 16)}` |

Дійсне число без специфікатора виводиться в науковому форматі, бо так
поводиться `WriteLn`. Для грошей і подібних значень пишіть `{X:0:2}`, а
для «людського» формату — `{FloatToStr(X)}`.

Те, чого немає у специфікаторах `WriteStr` (шістнадцятковий запис,
роздільники тисяч, вирівнювання ліворуч), робиться звичайною функцією у
виразі: `{IntToHex(X, 8)}`, `{FormatFloat('#,##0.00', X)}`,
`{PadRight(Name, 10)}` (`StrUtils`).

## 5. Тип результату

Результат — звичайний рядок рядкового типу режиму, як у рядкової
константи, присвоєної змінній: `AnsiString` з `{$H+}`, `UnicodeString` з
`{$modeswitch unicodestrings}`, `ShortString` з `{$H-}` (обрізається до
255 символів). Його можна присвоювати, передавати в підпрограми,
конкатенувати (`$'{A}' + ', ' + $'{B}'`) і використовувати в
`raise Exception.Create($'...')`.

Інтерпольований рядок **без виразів** — звичайна рядкова константа, тож
дозволений і в `const`:

```pascal
const
  Template = $'{{name}} — {{value}}';   // те саме, що '{name} — {value}'
```

З виразами це не константа: `const C = $'{X}'` — помилка компіляції.

Літерали з `{$codepage utf8}` обробляються так само, як звичайні рядкові
константи.

## 6. Перевірки компілятора

```pascal
WriteLn($'{Order.Totl}');          // Error: Identifier not found "Totl"
WriteLn($'{Name:5:2}');            // Error: Illegal use of ':' (точність лише для дійсних)
WriteLn($'{Obj}');                 // Error: Can't read or write variables of this type
N := $'{N}';                       // Error: Incompatible types: got "AnsiString" expected "LongInt"
WriteLn($'a{}b');                  // Error: Empty expression in an interpolated string
WriteLn($'a}b');                   // Error: Single "}" in an interpolated string, write "}}" for the character
WriteLn($'a{X');                   // Error: Unterminated expression "{" in an interpolated string
```

Повідомлення про вираз показують його справжню колонку у вихідному тексті.

## 7. Як це компілюється і скільки коштує

Сканер розбирає `$'...'` на частини. Далі можливі два варіанти:

- **усі частини — рядки чи символи без специфікаторів:** звичайна
  конкатенація, `'Hello, ' + Name + '!'`;
- **інакше:** `WriteStr` у тимчасовий рядок, тобто те саме, що
  `WriteStr(Tmp, 'Order #', Order.Id, ': ', Order.Total:0:2)`.

Розбору шаблону під час виконання немає. Заміри (x86_64-linux, `-O2`,
2 млн ітерацій):

| Варіант | Час |
|---|---|
| `Format('#%d from %s: %.2f', [...])` | 1340 мс |
| `$'#{Id} from {Name}: {Total:0:2}'` | 600 мс |
| `'#' + IntToStr(Id) + ... + FloatToStrF(...)` | 490 мс |
| `Format('#%s from %s', [...])` | 570 мс |
| `$'#{Name} from {Name}'` | 52 мс |

Інтерполяція приблизно вдвічі швидша за `Format` зі змішаними типами й
на порядок швидша з рядками. Ручна конкатенація з `IntToStr` трохи
швидша за гілку з `WriteStr`. Якщо рядок будується в гарячому циклі
мільйони разів, це варто знати.

## 8. Де лишити `Format` і параметри

- **Локалізація.** Перекладачу потрібен увесь шаблон, тож для
  `resourcestring` лишається `Format(SMessage, [...])`. Інтерполяція його
  не замінює.
- **SQL.** `$'... WHERE name = ''{Name}'''` — SQL-ін'єкція. Для запитів
  використовуйте параметри (`ParamByName('name').AsString := Name`).
- **HTML, JSON, командний рядок** — так само: значення треба екранувати
  відповідною функцією у виразі, інтерполяція сама нічого не екранує.

## 9. Обмеження

- Лише однорядкові рядки. Багаторядкові (`` ` ``, `'''`) не
  інтерполюються.
- Після `$'...'` не можна одразу дописати `#13` чи ще один літерал, як у
  `'a'#13'b'`. Пишіть `$'...' + #13`.
- Коментарі всередині виразу не підтримуються.
- У Delphi та upstream FPC такого синтаксису немає, код із `$'...'`
  компілюється лише цим компілятором із перемикачем.

## 10. Приклад

```pascal
{$mode objfpc}{$H+}
{$modeswitch interpolation}
uses SysUtils;

procedure PrintRow(Id: Integer; const Customer: string; Total: Double);
begin
  WriteLn($'|{Id:6}|{Customer:10}|{Total:10:2}|');
end;

function Describe(Id: Integer; const Customer: string; Total: Double): string;
begin
  Result := $'Order #{Id} from {Customer}: {Total:0:2} UAH';
end;
```

Повний приклад — [`examples/interpolation.pp`](../examples/interpolation.pp).

## 11. Тести

`tests/test/tinterp1`–`3` (з модулем `uinterp2`, `-gh`, без витоків):
- цілі, `Int64`, `QWord`, дійсні, `Boolean`, переліки, символи;
- ширина й точність, зокрема виразами;
- виклики функцій і рядкові константи у виразах, `{{`, `}}`, `''`;
- порожній рядок і рядок без виразів, константа в `const`, вкладена
  інтерполяція, конкатенація, цикл, `raise`, `ShortString`, рядок понад
  255 символів, `$FF`;
- дженерики (функція й клас, спеціалізовані з різними типами), модуль,
  `inline`, `initialization`, режим `delphi`, разом з `inlinevars`,
  `-gw -O3`;
- `UnicodeString` з `unicodestrings`, `{$codepage utf8}`, `{$H-}`.

`tinterp4`–`15` (`{%FAIL}`) — помилки:
- без перемикача;
- порожній вираз, одинична `}`, незакритий вираз, кінець рядка;
- клас, запис, вказівник;
- точність для рядка;
- невідомий ідентифікатор;
- не константа в `const`;
- рядок замість числа.
