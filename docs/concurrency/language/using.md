# Посібник користувача: оператор ресурсу `using .. do` (`{$modeswitch using}`)

Розділ 2.5 дорожньої карти ([roadmap.md](../roadmap.md)). Перемикач форку,
синтаксис близький до Oxygene (`using X := ... do`) і C# (`using`).

## 1. Навіщо

Тимчасовий об'єкт у Pascal звільняють так:

```pascal
Stream := TFileStream.Create('data.bin', fmOpenRead);
try
  Stream.ReadBuffer(Header, SizeOf(Header));
finally
  Stream.Free;
end;
```

Сім рядків замість одного. До того ж легко помилитися: поставити `Create`
всередину `try`, забути `Free` або переплутати порядок звільнення кількох
потоків. З `{$modeswitch using}` те саме записується так:

```pascal
{$modeswitch using}
...
  using var Stream := TFileStream.Create('data.bin', fmOpenRead) do
    Stream.ReadBuffer(Header, SizeOf(Header));
```

Компілятор генерує рівно той самий `try..finally`. Це не збирач сміття і
не підрахунок посилань, тож додаткових витрат немає.

`using` прибирає витоки та помилки в одному конкретному шаблоні: **об'єкт
створюється, використовується й знищується в одному місці**. Об'єкти, які
кладуть у поля чи списки або повертають із функцій, як і раніше, звільняє
їхній власник.

## 2. Увімкнення

```pascal
{$mode objfpc}{$H+}
{$modeswitch using}
```

Перемикач діє в усіх режимах (`objfpc`, `delphi`, `fpc` …). З ним `using`
стає зарезервованим словом. Без перемикача компілятор поводиться як FPC, і
`using` лишається звичайним ідентифікатором. Тож наявний код, де так названо
змінну чи поле, не ламається, поки перемикач не ввімкнено.

Для форми `using var` перемикач `inlinevars` не потрібен.

## 3. Синтаксис

```text
using_statement = "using" resource { "," resource } "do" statement
resource        = "var" ident [ ":" type ] ":=" expression
                | variable ":=" expression
```

**Нова змінна** (`using var`): видима лише в ресурсах, що йдуть після неї, і
в операторі після `do`. Тип виводиться з ініціалізації за тими самими
правилами, що й для `var X := ...` ([inline-vars.md](inline-vars.md)), або
вказується явно:

```pascal
using var List := TStringList.Create do ...
using var Obj: TObject := TStringList.Create do ...   // явний (базовий) тип
```

**Змінна з секції `var`** (класичний стиль Pascal, оголошення окремо від
коду): після оператора вона дорівнює `nil`, тож висячого посилання не
лишається:

```pascal
var
  Words: TStringList;
begin
  using Words := TStringList.Create do
    Words.Add('one');
  // тут Words = nil
```

Ресурсом може бути локальна чи глобальна змінна або параметр-значення. Поле,
властивість, елемент масиву чи виклик функції ресурсом бути не можуть
(«Variable identifier expected»).

**Кілька ресурсів** перелічуються через кому. Наступний ресурс може
використовувати попередній. Форми можна змішувати:

```pascal
using var Src := TFileStream.Create(A, fmOpenRead),
      var Dst := TFileStream.Create(B, fmCreate) do
  Dst.CopyFrom(Src, 0);
```

Оператор після `do` — один оператор, як у `while` чи `with`. Для кількох
використовуйте `begin..end`.

## 4. Семантика

`using var A := X, var B := Y do S` компілюється в:

```pascal
A := X;
try
  B := Y;
  try
    S;
  finally
    B.Free;
  end;
finally
  A.Free;
end;
```

Звідси випливають такі правила:

- **Звільнення у зворотному порядку**: спершу останній ресурс, потім перший.
- **Виняток, `Exit`, `Break`, `Continue`** усередині оператора звільняють
  усі ресурси, після чого виняток іде далі.
- **Невдалий конструктор.** Якщо виняток виникає в ініціалізації ресурсу, то
  звільняються лише ресурси, створені раніше. Частково створений об'єкт
  знищує сам конструктор (стандартна поведінка Object Pascal), подвійного
  звільнення немає.
- **`nil` безпечний**: `using var R: TFoo := nil do ...` нічого не звільняє.

Що саме викликається:

| Тип ресурсу | Звільнення в кінці оператора |
|---|---|
| клас | `TObject.Free`, навіть якщо в класі оголошено інший `Free` |
| COM-інтерфейс (`{$interfaces com}`, за замовчуванням) | присвоєння `nil`: лічильник посилань зменшується в кінці оператора, а не в кінці підпрограми |
| змінна з секції `var` | додатково `X := nil` після `Free` |
| інші типи: числа, записи, рядки, посилання на клас, CORBA-інтерфейси | помилка компіляції |

Для інтерфейсу `using` означає «звільнити своє посилання»: якщо об'єкт
тримає ще хтось, він живе далі.

## 5. Захист ресурсу

Усередині оператора ресурс доступний лише для читання, як змінна циклу
`for`. Помилкою компіляції є:

```pascal
using var R := TFoo.Create do
  R := TFoo.Create;          // Error: Illegal assignment to resource "R" of a "using" statement
using var R := TFoo.Create do
  Replace(R);                // var-параметр — та сама помилка
using A := TFoo.Create, A := TFoo.Create do ...   // та сама помилка
```

Так оператор гарантує, що звільняє саме той об'єкт, який створив.
Методи об'єкта, звісно, викликати можна (`R.Add(...)`, `R.Name := ...`).

`FreeAndNil(R)` усередині оператора не помилка: він обнуляє `R`, тож
`Free` у кінці отримує `nil`. Але **не викликайте `R.Free` чи `R.Destroy`
вручну**: змінна після цього не обнуляється, і об'єкт буде звільнено двічі.
Компілятор цього не відстежує, так само як і з `try..finally`.

`goto` всередину оператора чи з нього назовні заборонений («Jump in or
outside of an exception block»), так само як для `try..finally`.

## 6. Область видимості й час життя

- Змінна `using var` видима від свого оголошення до кінця оператора після
  `do`. Після нього ім'я вільне: сусідні оператори можуть знову оголосити
  `using var R`, зокрема з іншим типом.
- Змінна `using var` затіняє зовнішню змінну з тим самим ім'ям лише всередині
  оператора.
- Як і inline-змінна, вона розміщена в кадрі підпрограми. Об'єкт звільняється
  в кінці оператора, а не підпрограми.
- Анонімні функції можуть захоплювати ресурси. Не викликайте таку функцію
  після оператора: об'єкт уже звільнено.
- У дженериках тип ресурсу перевіряється під час спеціалізації.

## 7. Коли це корисно

| Сценарій | Приклад |
|---|---|
| файли й потоки | `TFileStream`, `TMemoryStream`, `TStringStream`, стиснення поверх файла |
| тимчасові контейнери | `TStringList` для розбору рядка, тимчасові `TList<T>`/`TDictionary<K, V>` |
| розбір даних | `GetJSON(...)`, `TXMLDocument`, `TIniFile` |
| база даних і мережа | `TSQLQuery` на один запит, `TFPHTTPClient` на один виклик, `TProcess` |
| графіка | тимчасовий `TBitmap`, модальна форма на один показ |
| тести й утиліти | тимчасові об'єкти кожного кроку |

Де `using` не допоможе: об'єкти з власником (`Owner`,
`TObjectList(OwnsObjects)`), фабрики, які повертають об'єкт, довгоживучі
сервіси, а також парні дії без об'єкта (`Enter`/`Leave` критичної секції).
Для одноосібного володіння, яке передається між підпрограмами, є
`TScoped<T>` ([../guides/smart-pointers.md](../guides/smart-pointers.md)).

## 8. Порівняння з `TScoped<T>` і `try..finally`

| | `try..finally` | `TScoped<T>` | `using .. do` |
|---|---|---|---|
| звільнення | вручну | у кінці підпрограми | у кінці оператора |
| нове в мові | — | ні (керований запис у RTL) | так (перемикач) |
| присвоєння змінній у блоці | дозволене (можливий витік) | за правилами `TScoped<T>` | помилка компіляції |
| передача власності далі | вручну | так | ні (лише локальний ресурс) |
| витрати | try-фрейм | неявний try-фрейм і запис-обгортка | try-фрейм |

## 9. Приклад

```pascal
{$mode objfpc}{$H+}
{$modeswitch using}
uses SysUtils, Classes, fpjson, jsonparser;

function ReadPort(const Config: string): Integer;
begin
  using var Json := GetJSON(Config) do
    Result := TJSONObject(Json).Get('port', 8080);
end;

function SortedLines(const FileName: string): string;
begin
  using var Lines := TStringList.Create do
    begin
      Lines.LoadFromFile(FileName);
      Lines.Sort;
      Result := Lines.CommaText;
    end;
end;
```

Повний приклад — [`examples/using_resources.pp`](../examples/using_resources.pp).

## 10. Відмінності від пропозиції та інших мов

- Пропозиція 4.2 у `proposals/modern_pascal_productivity_and_web_vision.md`
  писала `using Stream := ... do` для **нової** змінної. У форку нова змінна
  оголошується явно (`using var`), а `using X := ...` означає змінну з секції
  `var`. Так немає неоднозначності («оголошення чи присвоєння?») і зберігається
  можливість писати в класичному стилі з оголошеннями до `begin`.
- Oxygene викликає `Dispose` (`IDisposable`), C# викликає `Dispose()`. Форк
  викликає `TObject.Free`, тобто деструктор, як у звичайному коді FPC.
- У Delphi такого оператора немає. Код із `using` компілюється лише цим
  компілятором із перемикачем.

## 11. Тести

`tests/test/tusing1`, `tusing2`, `tusing4` (з модулем `uusing4`, `-gh`, без
витоків): момент і порядок звільнення, винятки в тілі та в конструкторі
наступного ресурсу, `Exit`/`Break`/`Continue`, `nil`, вкладені оператори,
повтор імені, затінення, вкладені підпрограми, головна програма, змінні
секції `var`, параметри й глобальні змінні (`nil` після оператора, також
після винятку), COM-інтерфейси, клас із власним `Free`, дженерики, разом з
`inlinevars`, захоплення анонімною функцією, режим `delphi`, модуль
(`inline`-функція, `initialization`), `-gw -O3`. `tusing3` — без перемикача
`using` є звичайним ідентифікатором. `tusing5`–`20` (`{%FAIL}`) — помилки:
без перемикача, присвоєння ресурсу (також змінній секції `var`, через
`var`-параметр і повтором у тому самому операторі), видимість після
оператора, тип не клас і не COM-інтерфейс (число, запис, CORBA-інтерфейс,
посилання на клас), поле і виклик функції як ресурс, `nil` без типу,
`using` як ідентифікатор із перемикачем, ресурс без ініціалізації,
`const`-параметр.
