# ForkJoin на практиці: рекомендації та рецепти

Як застосовувати `System.Threading.ForkJoin` разом з іншими нововведеннями
форку (стрілкові функції, змінні за місцем, `using`, кортежі, інтерполяція) у
типових задачах. Довідка з API — [forkjoin.md](forkjoin.md), рішення —
[ADR-0013](../adr/0013-forkjoin-fine-grained-tasks.md).

Усі приклади зібрано в програму
[`examples/forkjoin_recipes.pp`](../examples/forkjoin_recipes.pp): кожен рецепт
звіряє результат із послідовним обчисленням.

```sh
ppcx64 -O2 -Fu<дерево>/packages/vcl-compat/units/x86_64-linux docs/concurrency/examples/forkjoin_recipes.pp
./forkjoin_recipes
```

## 1. Що брати для якої задачі

| Задача | Інструмент |
|---|---|
| Обробити кожен елемент масиву, рядок зображення, запис | `TForkJoin.Each` |
| Порахувати суму, гістограму, статистику по великому масиву | `TForkJoin.Each` по шматках з локальними лічильниками |
| Рекурсивний алгоритм «поділи навпіл» (сортування, дерево, обхід) | `TForkJoin.Join` або вкладені `TTaskGroup` |
| Список незалежних робіт різного розміру (документи, файли вже в пам'яті, рахунки) | `TTaskGroup.Spawn(I, …)` на кожну роботу |
| Пошук зі зупинкою, щойно знайдено | `TTaskGroup` + спільний результат (+ `Cancel` для «будь-якого») |
| Довга фонова робота з продовженнями, скасуванням, статусом | `TTask`, `IFuture<T>` |
| Конвеєр стадій, виробник–споживач | `TChannel<T>` + `TTask` |
| Очікування мережі, файлів, бази | `async`/`await`, `fcl-eventloop` |

**Головне правило:** задача ForkJoin має *рахувати*. Якщо вона чекає (на
замок, канал, мережу, `Sleep`), вона займає воркер, а інші задачі стоять у
черзі. Для очікування є `TTask`, канали й `async`/`await`.

## 2. Сім правил

1. **Шматок має бути не меншим за кілька мікросекунд роботи.** Задача коштує
   десятки наносекунд; якщо тіло коротше — розбивайте не на елементи, а на
   шматки: `Each` з параметром `aGrain`, або `Each` по номерах шматків.
2. **Рахуйте локально, зливайте раз на шматок.** `InterlockedIncrement` на
   спільній змінній у кожній ітерації змушує всі ядра змагатися за одну
   кеш-лінію і з'їдає весь виграш (рецепт 2).
3. **Результат — у свій елемент масиву.** `Results[I] := F(I)` з різних задач не
   потребує жодної синхронізації: кожна пише у свою комірку (рецепти 4, 5).
4. **Передавайте індекс аргументом, а не захопленою змінною циклу:**
   `Group.Spawn(I, Idx => Work(Idx))`. Анонімна функція захоплює змінну, а не
   значення, тож `Spawn(() => Work(I))` у циклі побачить «чуже» `I`.
5. **Параметри `var`/`out` захопити не можна** — скопіюйте в локальну змінну або
   передайте вказівник (рецепт 1). Відкритий масив (`array of T` як параметр)
   теж скопіюйте в динамічний масив.
6. **Свій генератор випадкових чисел на шматок.** `Random` має спільний стан:
   з кількох потоків він і повільний, і псує послідовність (рецепт 8).
7. **Винятки не треба ловити в кожній задачі.** Перший виняток групи прилетить
   із `Wait`/`Each`/`Join` у потоці, що чекає; задачі, які ще не почались,
   пропускаються (рецепт 7).

## 3. Рецепти

### 3.1. Обробка зображення по рядках

Рядки незалежні — `Each` по номерах рядків. Параметр-масив замінено
вказівником, бо захоплювати `var`-параметри не можна.

```pascal
procedure Brighten(aPixels: PByte; aWidth, aHeight, aDelta: Integer);
begin
  TForkJoin.Each(0, aHeight - 1, Y =>
    begin
      var Row := aPixels + Y * aWidth;
      for var X := 0 to aWidth - 1 do
        Row[X] := Min(255, Row[X] + aDelta);
    end);
end;
```

Так само: фільтри, перетворення кольору, масштабування, обробка кадрів
відео, рендер рядків таблиці.

### 3.2. Гістограма й статистика: локальні лічильники

Кожен шматок рахує свою гістограму в стеку, а спільну доповнює один раз.

```pascal
TForkJoin.Each(0, CHUNKS - 1, C =>
  begin
    var Local: THistogram;
    FillChar(Local, SizeOf(Local), 0);
    for var I := C * Len div CHUNKS to (C + 1) * Len div CHUNKS - 1 do
      Inc(Local[Data[I]]);
    for var B := 0 to 255 do
      if Local[B] <> 0 then
        InterlockedExchangeAdd64(Total[B], Local[B]);
  end, 1);
```

`aGrain = 1`: кожен номер шматка — окрема одиниця роботи, бо шматки вже
великі. Так само: сума й середнє, мінімум/максимум, підрахунок слів у
корпусі, агрегація логів.

### 3.3. Рекурсивне сортування: `Join`

Після розбиття дві частини незалежні. Малі частини — послідовно: інакше
задач стане більше, ніж роботи.

```pascal
procedure ParallelQuickSort(A: PInt64; Lo, Hi: Integer);
begin
  if Hi - Lo < 20000 then
  begin
    SequentialQuickSort(A, Lo, Hi);
    Exit;
  end;
  { ... розбиття навколо Pivot, обмін через кортеж: (A[I], A[J]) := (A[J], A[I]) ... }
  TForkJoin.Join(() => ParallelQuickSort(A, Lo, J),
                 () => ParallelQuickSort(A, I, Hi));
end;
```

`Join` виконує першу гілку в поточному потоці, а поки чекає на другу —
виконує інші задачі, тож глибока рекурсія не блокує воркери. Так само:
сортування злиттям, обчислення над деревом відрізків, «поділи й володарюй».

### 3.4. Дерево: група на дітей вузла

Розмір дерева каталогів (вже прочитаного в пам'ять), обхід AST, обчислення
над деревом сцени. Діти — в одній групі, глибше — послідовно.

```pascal
function TreeSize(aNode: PNode; aDepth: Integer): Int64;
begin
  if aDepth >= 3 then
    Exit(SequentialTreeSize(aNode));
  var Sizes: array of Int64;
  SetLength(Sizes, Length(aNode^.Children));
  using var Group := TTaskGroup.Create do
  begin
    for var I := 0 to High(aNode^.Children) do
      Group.Spawn(I, Idx => Sizes[Idx] := TreeSize(aNode^.Children[Idx], aDepth + 1));
    Group.Wait;
  end;
  Result := aNode^.Size;
  for var S in Sizes do
    Inc(Result, S);
end;
```

Вкладені групи безпечні: `Wait` усередині задачі виконує інші задачі, а не
блокує воркер. `using var` звільняє групу навіть після винятку.

### 3.5. Незалежні роботи різного розміру

Документи, рахунки, зображення в пам'яті — по задачі на роботу. Роботи різні
за розміром; воркер, що звільнився, краде наступну, тож довгі роботи не
затримують решту.

```pascal
using var Group := TTaskGroup.Create do
begin
  for var I := 0 to High(Docs) do
    Group.Spawn(I, Idx => Counts[Idx] := CountWords(Docs[Idx]));
  Group.Wait;
end;
```

Рядки й інші керовані типи всередині задач працюють як звичайно.

### 3.6. Пошук із ранньою зупинкою

**Перший збіг.** Шматки після вже знайденого збігу виходять одразу; спільний
результат оновлюється CAS-ом, лише якщо новий індекс менший.

```pascal
Group.Spawn(C, Chunk =>
  begin
    for var I := Chunk * CHUNK to Min(High(Values), (Chunk + 1) * CHUNK - 1) do
    begin
      if I > Best then
        Exit;
      if IsPrime(Values[I]) then
      begin
        var Old: Int64;
        repeat
          Old := Best;
        until (I >= Old) or (InterlockedCompareExchange64(Best, I, Old) = Old);
        Exit;
      end;
    end;
  end);
```

**Будь-який збіг** («чи є хоч один невалідний запис»): тут доречний
`Group.Cancel` — задачі, що ще не почались, пропускаються.

```pascal
if IsPrime(Values[I]) then
begin
  Found := True;
  Group.Cancel;
  Exit;
end;
```

Не використовуйте `Cancel` для «першого» збігу: він пропустить і ті шматки
*до* знайденого, що ще не почались, і результат буде не першим.

### 3.7. Валідація: виняток доходить до викликача

```pascal
TForkJoin.Each(0, High(Ages), I =>
  begin
    if (Ages[I] < 0) or (Ages[I] > 150) then
      raise EInvalidRecord.Create($'record {I}: age {Ages[I]}');
  end);
```

`Each` кидає перший виняток у потоці, що його викликав; інші винятки
звільняються, решта групи скасовується. Обробник — звичайний
`try … except on E: EInvalidRecord`.

### 3.8. Монте-Карло: свій генератор на шматок

```pascal
TForkJoin.Each(0, CHUNKS - 1, C =>
  begin
    var State: UInt64 := UInt64(C) * 2654435761 + 1;   // xorshift64
    var Hits: Int64 := 0;
    for var I := 1 to aSamples div CHUNKS do
    begin
      State := State xor (State shl 13);
      State := State xor (State shr 7);
      State := State xor (State shl 17);
      { X, Y з двох половин State; Inc(Hits), якщо точка в колі }
    end;
    InterlockedExchangeAdd64(Inside, Hits);
  end, 1);
```

Насіння від номера шматка робить результат відтворюваним незалежно від
того, який потік узяв шматок. Так само: симуляції, стохастичні тести,
бутстреп-оцінки.

## 4. Типові помилки

| Помилка | Що станеться | Як правильно |
|---|---|---|
| `Spawn(() => Work(I))` у циклі | задачі бачать змінне `I` | `Spawn(I, Idx => Work(Idx))` |
| `InterlockedIncrement(Total)` у кожній ітерації | ядра змагаються за одну кеш-лінію, паралельна версія повільніша за послідовну | локальний лічильник, злиття раз на шматок |
| Задача на кожен елемент мільйонного масиву з коротким тілом | накладні витрати більші за роботу | `Each` (сам ділить на шматки) або `aGrain` |
| `Sleep`, очікування замка чи каналу в задачі | воркер простоює, інші задачі стоять | `TTask`, `TChannel`, `async`/`await` |
| `Random` у задачах | спільний стан, повільно й невідтворювано | свій генератор у кожному шматку |
| `Cancel` для «першого» збігу | пропущено шматки до збігу | спільний мінімум через CAS |
| Захоплення `var`-параметра чи відкритого масиву | не компілюється | локальна копія або вказівник |

## 5. Разом з іншими нововведеннями

| Нововведення | Де допомагає з ForkJoin |
|---|---|
| Стрілкові функції `X => …` | тіло задачі на місці виклику, без окремої процедури |
| Змінні за місцем `var X := …` | локальні лічильники й межі шматка прямо в тілі задачі |
| `using var Group := TTaskGroup.Create do` | група звільняється (і дочікується) навіть після винятку |
| Кортежі `(A, B) := (B, A)` | обмін при розбитті в сортуванні; межі шматка як `(Lo, Hi)` |
| Інтерполяція `$'…'` | повідомлення винятків із задач: `$'record {I}: age {Ages[I]}'` |
| Методи для записів (`extensionmethods`) | обчислення над елементом поруч із даними: `Items[I].Normalized` |
